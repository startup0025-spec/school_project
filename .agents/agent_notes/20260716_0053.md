[1_WHAT] (State & Context):
> Sentinel approved Cycle 2 and requested analysis on station filtering and mapping for Cycle 3.
> Analyzed how `waterStationName` (e.g., '세병교', '동천교') on the `Place` interface will be used to filter raw API results.

[2_HOW] (Action & Details):
> - Station Mapping: `waterStationName` refers to specific station names ('부곡교', '세병교', '이섭교', '동천교', '세월교').
> - Designed extraction functions:
>   - `extractWaterLevelForPlace`: Searches the `item` array for `siteName === waterStationName` and maps to `RiverWaterLevel`. Returns `null` if not found or if `waterStationName` is undefined.
>   - `extractWaterQualityForPlace`: Searches the `item` array for `locNamel === waterStationName` and maps to `RiverWaterQuality`. Returns `null` if not found or if `waterStationName` is undefined.
> - Handled edge cases: missing matching station name and undefined `waterStationName` (e.g., sea spots).

[3_WHY] (Reasoning & Dependency):
> - This logic decouples the raw array payload retrieval from station-specific usage, letting the UI and audio engines query specific locations easily without managing array lookups.
