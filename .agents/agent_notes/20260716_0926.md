[1_WHAT] (State & Context):
> Kakao Map API 연동 코드에 대한 Cycle 5 Critic 피드백을 반영하여 `map.tsx`, `local_places.ts`, `mockData.ts` 파일을 수정하고 최종화하는 작업을 수행합니다.
> 현재 상황은 Cycle 5에서 제안된 파일들이 존재하나, 몇 가지 성능 및 안정성 취약점(속도 제한 부재, WebView 문자열 직렬화 이스케이프 오류, 마커 정리 메모리 누수 및 프로토타입 오염, WebGL 오류 리스너 문제 및 프로세스 비정상 종료 시 복구 불가, 거리/도보 시간 계산 NaN 대응 미흡 등)이 지적되어 개선이 필요한 상태입니다.

[2_HOW] (Action & Details):
> 1. `local_places.ts`:
>    - `FRESHNESS_THRESHOLD = 30000` (30초) 상수를 도입하여 짧은 시간 내의 반복적인 CDN 요청을 차단하는 timestamp 기반의 속도 제한 추가.
>    - `subscribeToPlacesCache`에서 리스너 등록 개수가 15개를 초과할 경우 메모리 누수를 경고하는 `console.warn` 개발자 경고 추가.
> 2. `map.tsx`:
>    - `window.updateSpots` 함수가 string 형태의 JSON 대신 자바스크립트 객체 배열(array)을 직접 받아 처리하도록 WebView 내부 스크립트 수정.
>    - React Native 단에서 single/double quote nesting 문제를 피하기 위해 `JSON.stringify(spotsData)`를 직접 템플릿 리터럴에 삽입하여 WebView로 주입하도록 변경.
>    - WebView 내부 `updateSpots` 마커 정리 루프(`for (var id in markers)`)에서 `hasOwnProperty` 확인을 추가하고, 마커 객체를 지도에서 제거하기 전에 `kakao.maps.event.clearInstanceListeners(markers[id])` 호출을 통해 이벤트 리스너 제거 및 메모리 누수 방지.
>    - 불필요한 WebGL 컨텍스트 유실 리스너(`webglcontextlost`) 제거.
>    - `<WebView>` 컴포넌트에 `onContentProcessDidTerminate` 콜백을 등록하여 WebContent 프로세스가 OS에 의해 비정상 종료되었을 때 지도를 reload하도록 복구 로직 추가.
>    - `getHaversineDistance` 내의 좌표값들에 대해 `null`, `undefined`, `typeof !== 'number'` 검사를 보강하여 NaN 발생을 원천 차단.
>    - `getWalkTime`에서 계산된 도보 시간 분(minutes)이 120분을 초과할 경우 `'도보 2시간 이상'`을 반환하거나 `place.walk` 폴백 적용.
> 3. `mockData.ts`:
>    - Cycle 5 기준 최종 데이터 검증 및 모듈 확인.

[3_WHY] (Reasoning & Dependency):
> - 속도 제한은 레고 놀이방 입구에서 30초에 한 번만 입장할 수 있게 문지기를 세우는 것과 같습니다. 무한정 들어가려 하면 놀이방이 미어터지기 때문입니다(서버 과부하 방지 및 배터리 절약).
> - JSON 문자열을 작은따옴표로 감싸서 전달하면 데이터 안에 작은따옴표가 들어있을 때 글자가 깨지거나 고장이 납니다. 장난감 상자를 포장지로 감싸는 대신 상자 자체를 직접 넘겨주는 것이 안전합니다(문자열 파싱 탈출 오류 해결).
> - 장난감을 다 놀고 상자에 넣을 때, 장난감에 붙어 있는 이름표와 끈들을 다 떼어내고 넣어야 상자가 깨끗하게 정리됩니다(이벤트 리스너 해제 및 메모리 누수 방지).
> - 태블릿 화면이 갑자기 픽 꺼지면 다시 껐다 켜는 버튼을 눌러서 켜주는 것처럼 프로세스 종료 시 자동 새로고침을 적용합니다(안정성 극대화).

> - 저장 후 TypeScript 컴파일 오류 여부를 확인하고 검증합니다.
